# 本地写作与发布准备

## 新建草稿

```sh
npm run new:post -- "文章标题"
```

在 `src/content/drafts/` 编辑生成的 Markdown。草稿不进入正式页面、搜索或订阅，但 Git 跟踪的草稿不是私密存储，不放秘密。本地运行 `npm run dev -- --host 127.0.0.1` 后访问 `/draft-preview/`，可以查看草稿列表和正文。预览仅在开发模式生成，带 noindex；noindex 不是访问控制，开发服务器不要暴露到公开网络。生产构建不生成这些页面。

## 准备正式文章

```sh
npm run publish:post -- "2026-09-05-文章标题.md" my-stable-slug "文章摘要"
npm run test:writing
npm run verify
```

第一个参数相对于 drafts 目录。slug 只允许小写 ASCII 字母、数字和中划线，发布路径为 `/posts/my-stable-slug/`，发布后不要随意改动。历史文章继续使用 legacyPath。

命令要求草稿有 title、有效 date、draft=true 和非空正文；摘要不超过 320 字符。拒绝目录外源文件、已有发布路径或目标文件覆盖。旧站迁移草稿带 legacy 信息的，需要人工处理，不能用此命令直接迁移。

成功时先以禁止覆盖方式写入 blog 文件，再删除未发生并发改动的源草稿。若写入后发现源稿变化则报错，两份文件都保留，人工比对后处理。该流程不是跨文件事务；中断后检查两份文件，不盲目重复执行。

此命令只做本地准备，不自动格式化正文、不提交、不推送、不部署。完整检查若要求格式化，审阅格式化差异后再验证。检查 Git diff，确认标题、日期、摘要、正文和路径，再按发布分支的 PR 流程推送。当前尚未完成首次生产切换，不能把任意分支推送当作正式上线。

6 项隔离命令测试覆盖成功、非法 slug、路径冲突、历史草稿、目录外来源、空正文。新文章 `/posts/…/` 已经临时构建验证：RSS/Atom 和前后导航从 84 增至 85，清理后恢复 84。完整 verify 通过。

开发专用草稿预览已逐一验证 19 篇返回 HTTP 200 且含 noindex；生产隔离另行通过构建检查。仍待更多中断/并发故障测试，以及发布集成后的 CI 验收。测试不代表已获生产发布授权。
